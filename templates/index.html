    1. Introduction

    The Unified Network Monitoring System (UNMS) is a specialized platform developed to bridge the gap between network administration and digital forensics. It provides a centralized interface for observing, analyzing, and securing network infrastructures.

    2. Key Features

    🔍

    Network Discovery

    Automatically scans the local environment to identify active hosts, MAC addresses, and device types.

    📊

    Traffic Analysis

    Monitors bandwidth usage and data packets to identify bottlenecks and optimize network performance.

    🛡️

    Security Auditing

    Logs connection attempts and detects anomalies indicating unauthorized access or security threats.

    📈

    Real-time Reporting

    Generates visual summaries of system uptime and latency for quick decision-making.

    3. The Forensic Connection

    As a student of Digital & Cyber Forensic Science, I developed this tool to focus on Network Observability. By capturing live data flow, this system provides the baseline evidence needed for forensic investigation and incident response.

    🚀 Getting Started

    1

    Open the Network Dashboard

    Click Network in the top navigation bar to access the main monitoring panel. You will see three status cards: Scan Status, Connected Devices, and Traffic Usage.

    2

    Run a Network Scan

    Press the ⟳ Scan Network button. UNMS will sweep the local subnet, detect active hosts, and update the device table with IP addresses and MAC addresses automatically.

    3

    Review Connected Devices

    The device table lists every discovered host. Each row shows the device name, IP address, MAC address, and current status. Hover over a row to highlight it. Rows update in real time after each scan.

    4

    Check the Event Log

    Navigate to Logs to view a timestamped history of all scanned devices. Use the search box to filter by device name and the date picker to narrow down by date.

    5

    Understand the Status Cards

    Scan Status shows whether a scan is running or complete. Connected Devices displays the live host count. Traffic Usage estimates the bandwidth consumed during the last scan cycle.

    ❓ Frequently Asked Questions

    What does the Scan Network button actually do?▼
    The scan button triggers an ARP sweep of the local subnet. It sends broadcast packets and listens for replies from active hosts, then populates the device table with each responding IP and its corresponding MAC address. The traffic card updates with an estimated bandwidth reading after the sweep completes.
    Why does a device show "Offline" in the status column?▼
    A device is marked Offline when it did not respond to the most recent scan. This can happen if the device is powered off, has gone to sleep, is blocking ICMP/ARP probes via a firewall, or has changed its IP due to a DHCP reassignment. Re-run the scan after ensuring the device is active.
    How is Traffic Usage calculated?▼
    Traffic Usage reflects the total bytes transmitted and received by the monitoring interface during the last scan window. It is a snapshot, not a cumulative counter — it resets with each new scan. For continuous traffic monitoring, a dedicated packet-capture tool such as Wireshark or ntopng is recommended alongside UNMS.
    Can UNMS detect devices on other subnets?▼
    By default, UNMS only scans the local subnet of the host machine. Devices on different subnets require either routing configuration or multiple UNMS instances deployed per subnet. Cross-subnet ICMP ping sweeps can be enabled in the backend config if the network gateway permits forwarded ICMP.
    How do I search and filter the event log?▼
    Go to the Logs page. Type any keyword — device name, IP address, or MAC address — in the search box to instantly filter matching rows. Use the date picker to restrict results to a specific day. Both filters work together, so you can search for "Laptop" on "2025-06-01" simultaneously.
    Is UNMS suitable for forensic evidence collection?▼
    UNMS is designed as an observability and baseline tool for Digital & Cyber Forensic Science students. The log history provides timestamped connection records that can support incident timelines. For court-admissible forensic capture, logs should be exported, hashed, and stored using a write-once evidence management process.
    What does the MAC address column tell me?▼
    The MAC (Media Access Control) address is a hardware identifier unique to each network interface. The first three octets (OUI) identify the device manufacturer — for example, a MAC starting with "B8:27:EB" indicates a Raspberry Pi. This is useful in forensic analysis for identifying unknown or rogue devices on the network.

    🔧 Troubleshooting

    !

    Scan completes but no devices appear

    Ensure the backend server is running and the scanning module has permission to send ARP packets (may require root/administrator privileges). Also confirm the host machine is connected to the network via the correct interface.

    !

    A known device is missing from the table

    The device may be on a different subnet, using a VPN, or blocking broadcast packets. Try pinging the device manually to confirm reachability, then re-run the scan. Check that the DHCP lease for the device has not expired and reassigned to a new IP.

    !

    Traffic Usage always shows "—"

    Traffic data requires the backend monitoring agent to be actively capturing on the network interface. If the agent is not running or the interface name is misconfigured in the settings, the card will show no data. Verify the interface name matches your operating system (e.g. eth0, en0, wlan0).

    !

    Log filter returns no results

    Check that the date format in the date picker matches the format stored in the log (YYYY-MM-DD). Clear both the search box and date picker and try again. If the log table is empty, run a scan first to generate new entries.
